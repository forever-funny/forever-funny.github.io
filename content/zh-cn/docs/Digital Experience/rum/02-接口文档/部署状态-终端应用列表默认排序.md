# 部署状态 - 终端应用列表默认排序

## 1. 文档目标

说明控制台 **部署配置 → 部署状态 → 终端应用** 列表的默认查询排序逻辑，以及前端排序状态为何不影响结果。

对应页面路径示例：`/deploy/manage/application`。

## 2. 结论

默认（也是当前实际生效的）排序为：

1. **主排序**：`updateTime` **DESC**（最近更新的应用在前）
2. **次排序**：`detectedName` **ASC**（应用识别名称 / 列表「应用名称」字典序升序）

SQL 原文：

```sql
order by updateTime desc, detectedName asc
```

因此列表看起来不按「应用别名」「应用 ID」有序是预期行为；同页「当前状态」文案相同也不参与排序。

## 3. 调用链

```text
前端 ConfigMonitorTerminal
  → POST /rest/rum/settings/monitor/appListQuery
  → MonitorController.appListQuery
  → RumMonitorServiceImpl.appListQuery
  → CMDBServiceImpl.searchInstanceWithPage(ModelTypeEnum.APP, ...)
  → RumQueryServiceAppMapper.searchAppList
  → entity.app（ORDER BY updateTime desc, detectedName asc）
  → PageHelper 分页
```

### 3.1 前端

| 项 | 说明 |
|----|------|
| 组件 | `view/rum/src/packages/configurationModule/ConfigMonitorTerminal/ConfigMonitorTerminal.tsx` |
| 路由组件名 | `ManageApplication`（webpack 映射到上述组件） |
| 请求 | `POST /rest/rum/settings/monitor/appListQuery`，body 含 `pageNo`、`pageSize`、`searchText` |
| 排序参数 | 组件内虽有 `sortName` / `sortOrder` 状态，并在 `handleChange` 中更新，但 **`getData` 未把排序字段传给后端** |

因此：表头点击排序（若有）目前无法改变服务端默认排序；列表顺序完全由 SQL `ORDER BY` 决定。

### 3.2 后端

| 层 | 类 / 方法 |
|----|-----------|
| Controller | `framework/plugins/rum/rum-core/.../settings/controller/MonitorController.java` → `appListQuery` |
| Service | `RumMonitorServiceImpl.appListQuery`：组装 `userId` / `envId` / 筛选条件，**不设置 sort** |
| CMDB | `CMDBServiceImpl.searchInstanceWithPage`：`PageMethod.startPage` + `searchAppList` |
| Mapper XML | `rum-database/.../RumQueryServiceAppMapper.xml` → `searchAppList` |

`searchAppList` 关键字段映射（与排序相关）：

| SQL 字段 | 含义 | 列表展示 |
|----------|------|----------|
| `updateTime` | 应用更新时间 | 不在截图主列中直接展示，但是排序主键 |
| `detectedName`（结果别名 `name`） | 应用识别名称 | 「应用名称」 |
| `customizedName`（结果别名 `alias`） | 应用别名 | 「应用别名」——**不参与默认排序** |
| `md5` | 应用 ID（MD5） | 「应用 ID」——**不参与默认排序** |

## 4. 筛选与排序的关系

`RumMonitorServiceImpl` 将 `searchText` JSON 解析为：

| keyword | 参数 | 含义 |
|---------|------|------|
| 1 | `name` | 应用别名模糊匹配（`customizedName`） |
| 2 | `platform` | 应用类型 |
| 3 | `state` | 监控状态 |
| 4 | `detectedName` | 应用识别名称模糊匹配 |
| 5 | `md5` | 应用 MD5 精确匹配（含 OpenAPI 场景） |

筛选只影响 `WHERE`，**不改变** `ORDER BY updateTime desc, detectedName asc`。

## 5. 与「最近 3 天无地址上报」状态的关系

列表「当前状态」中「最近 3 天无地址上报数据」等文案，来自后续是否查到近期上报数据中心信息（`CMDBServiceImpl` 内 `getAppDataCenter` 等，按近 N 天时间窗查指标），属于**行级展示 enrichment**，**不是排序字段**。
