# 知识库更新协议

> 本文件定义知识库的更新触发条件、更新流程和修订记录格式。

## 更新触发场景

### A. 纠错型更新（高优先级）

**触发条件**：对话中发现知识库文档内容与实际代码不符。

**处理方式**：
1. 在对应文档中直接修正错误内容
2. 在文档末尾"修订记录"表追加一行
3. 如 kb-index.md 中的关键词描述也受影响，同步更新

**示例**：
- 发现 `MauLicenseService.configFilter()` 逻辑顺序描述有误（原文写"先查超量再查 Bitmap"，实际为"先查 Bitmap 再查超量"）
- 修正文档中对应章节的描述
- 追加修订记录

### B. 增量型更新（中优先级）

**触发条件**：对话中诊断出新问题根因、梳理出新逻辑链路，且知识库中未记录。

**处理方式**：
1. 判断属于哪个主题目录
2. 如果已有对应文档：在文档相关章节追加内容
3. 如果是新主题：在对应主题目录下新建文档，并更新 kb-index.md 和 README.md
4. 在文档末尾"修订记录"表追加一行

**示例**：
- 对话中梳理出"RUM 健康评分默认规则对崩溃率 100% 仍打 97.42 分"的根因（使用崩溃计数而非崩溃率）
- 在 `07-代码异常与修复状态/` 或新建 `12-健康评分/` 下追加文档
- 更新 kb-index.md 添加新关键词

### C. 变更型更新（高优先级）

**触发条件**：代码变更导致原有逻辑发生变化。

**处理方式**：
1. 找到受影响的文档
2. 更新对应章节，标注变更前后差异
3. 在修订记录中追加变更说明
4. 如变更影响 kb-index.md 关键词映射，同步更新

**示例**：
- `problemId` 字段重命名为 `questionId`，涉及多个接口和表
- 在 `07-代码异常与修复状态/代码异常-修复状态与崩溃记录页.md` 中更新字段说明
- 在 `02-接口文档/` 相关文档中更新接口字段
- 追加修订记录

### D. 新文档型更新（低优先级）

**触发条件**：对话中梳理出全新主题，知识库中没有对应文档。

**处理方式**：
1. 确定属于哪个主题目录（01-12），或是否需要新建主题目录
2. 创建新文档：**必须**带 YAML front matter，且 **`title` 必填**（见下方模板）；正文风格与已有文档一致
3. 更新 kb-index.md，添加新关键词到路由表
4. 更新 README.md 文档速查矩阵
5. 在新文档末尾添加"修订记录"表

#### 新文档强制模板（缺 `title` 视为不合格，不得提交）

```markdown
---
title: 页面标题（侧栏与浏览器标题；建议与正文一级标题一致）
weight: 10
description: 一句话摘要（可选但推荐）
---

# 页面标题

正文……

## 修订记录

| 日期 | 修订类型 | 修订内容 | 依据 |
|------|---------|---------|------|
| YYYY-MM-DD | 增量 | 新建文档 | 对话/源码 |
```

也可用 Hugo 脚手架生成（会自动带 `title`）：

```bash
hugo new content/zh-cn/docs/digital-experience/rum/0X-主题目录/文档名.md
```

## 更新流程

```
对话中产生新认知
    ↓
模型提示："本次对话发现 xxx 可能需要更新到知识库，是否需要我更新？"
    ↓
用户确认
    ↓
切到 Agent 模式
    ↓
模型执行更新：
  1. 读取目标文档当前内容
  2. 修改/追加相关章节（新建文档必须含 front matter `title`）
  3. 追加修订记录
  4. 如需要，更新 kb-index.md 和 README.md
    ↓
更新完成，模型报告变更摘要
```

## 修订记录格式

每份文档末尾维护一个修订记录表。新建文档时即添加空表。

```markdown
## 修订记录

| 日期 | 修订类型 | 修订内容 | 依据 |
|------|---------|---------|------|
| 2026-07-11 | 纠错 | 修正 configFilter 逻辑顺序：原文"先查超量再查 Bitmap"改为"先查 Bitmap 再查超量" | 源码 MauLicenseService.java 验证 |
| 2026-07-11 | 增量 | 新增"健康评分默认规则"章节 | 对话诊断 + HealthScoreServer.java 源码 |
```

### 修订类型枚举

| 类型 | 说明 |
|------|------|
| 纠错 | 修正文档中与实际代码不符的描述 |
| 增量 | 新增知识库中未记录的内容 |
| 变更 | 代码变更导致文档内容需要更新 |
| 结构 | 文档结构调整（非内容性变更） |
| 合并 | 多份文档合并为一份 |

## 定期审查建议

### 月度审查
每月让模型做一次知识库与源码的一致性检查：

> "请读取知识库中 [主题名] 相关文档，对比 newonexm 仓库当前源码，找出过时内容"

### 版本升级审查
当 newonexm 仓库有大版本变更时：

> "本次版本升级涉及 RUM 模块的 xxx 变更，请检查知识库中哪些文档需要更新"

### 关键词覆盖审查
定期检查 kb-index.md 是否覆盖了最近新增的业务概念：

> "请检查 kb-index.md 关键词路由表是否覆盖了最近对话中出现的新关键词"
